// system_architecture

Four core
systems.

Sunsets’ technology is organised into four distinct systems. Each operates independently but integrates into a unified experience. Phase 1 relies entirely on commercially available components. The custom build work is Phase 2.

Display & Visual
System 01
🖥️
Ready

High-definition LED display panels installed within each booth, rendering 4K (Phase 1) to 8K (Phase 2) sunset scenes. Bezel-less configuration creates an immersive window effect. Dynamic overlays show local time, city name, and live conditions.

Samsung The Wall / LG DVLED — commercial display solutions
Minimum 4K @ 60fps per booth — 8K preferred at scale
Bezel-less or floating frame installation
Dynamic HDR for sunset colour fidelity
Overlay system: city, time, scene countdown
Content & Streaming
System 02
📡
Partial

Phase 1: pre-produced 4K/8K looped content library. Phase 2: live feeds from camera rigs at partner city rooftops, delivered via CDN with low-latency encoding. The scene management dashboard controls which booth shows which scene in real time.

Phase 1: Cinematic 4K loops, produced on location per city
Phase 2: Live RTMP/SRT feeds, 4K @ 30fps minimum
CDN: Cloudflare Stream / AWS IVS for low-latency global delivery
Scene CMS: custom dashboard for real-time booth assignment
Redundancy: local NVMe playback backup if feed drops
Multi-Sensory
System 03
🌿
Ready

Scent diffusion, directional audio, and atmospheric lighting — the three non-visual sensory layers. All three systems use commercially available professional hardware. The integration layer (synchronising all three to the active scene) requires custom software.

Scent: Prolitec / Aromatec diffusion units ($200–$500/booth)
Audio: d&b audiotechnik / Bose Pro directional speakers
Lighting: Lutron or ETC scene-linked control per booth
Sync layer: API bridge between scene CMS and sensory hardware
Scent cartridges: 18+ city-specific formulas, supplied centrally
Operations & Loyalty
System 04
⚙️
To Build

Booking system, Sunsets Passport loyalty programme, and the venue management dashboard. Booking integrates with an existing hospitality platform (SevenRooms or ResDiary). The Passport app is bespoke — it's the primary retention and cross-venue engagement tool.

Booking: SevenRooms or ResDiary API integration
Passport: native iOS/Android app (React Native)
Stamp system: NFC or QR per booth, recorded per user
Loyalty engine: discount logic, cross-venue passport tracking
Venue dashboard: real-time occupancy, scene control, event mode

// prototype_sourcing

What to source
for the first physical mock-up.

The immediate sourcing goal is not to buy a complete venue. It is to prove one destination booth at full quality and use that prototype to lock the design, hardware architecture and cost model.

Architectural Display

Fine-pitch LED, curved or corner-capable modules, service access, heat management and colour performance strong enough for dark hospitality interiors. The screen must read as a window, not a television.

Integrated Booth

Custom seating, concealed lighting, acoustic treatment, ventilation and millwork engineered around the display. Prioritise modular fabrication so one booth system can be adapted across multiple cities.

Sensory Control

Directional audio, dimmable scene lighting, scent delivery and a simple control layer that can switch the full atmosphere together. Prototype reliability matters more than software sophistication.

// open_questions.md

What still
needs deciding.

These are the known unknowns — decisions that need to be made before or during the pilot phase. Logging them here so nothing gets missed.

High Priority
Which booking platform? SevenRooms vs ResDiary vs custom.
Affects integration timeline and cost significantly. SevenRooms has better API docs but higher per-venue cost. Decision needed before Month 2.
High Priority
Passport app: native vs React Native vs web app for v1?
Native gives best NFC integration. React Native is faster to build. Web app (PWA) is fastest and cheapest for Phase 1 MVP. Recommendation: PWA for pilot, native for Phase 2.
Medium Priority
How many cities in the initial 4K loop production run?
10 cities (pilot booths only) vs 16–18 cities (first rotation ready at launch). Cost difference is significant but rotation from day 1 is a strong retention story.
Medium Priority
Scent vendor: Prolitec vs Aromatec vs custom manufacturer?
Prolitec has the widest commercial install base. Aromatec allows fully custom cartridge formulation. Custom manufacturer is cheapest at scale. Pilot can use Prolitec, then switch at scale.
Lower Priority
Phase 2 camera rig: who owns and maintains the equipment at partner cities?
Sunsets-owned (higher capex, full control) vs partner-hosted (lower cost, reliability risk) vs third-party camera rental (most flexible). Needs to be in the partnership agreement template.
Lower Priority
What is the fallback experience when a live feed drops?
Auto-switch to loop of same city (seamless, invisible to guest) vs a "technical pause" notification vs a full system alert. Recommendation: silent auto-fallback to loop. Guest never knows.
